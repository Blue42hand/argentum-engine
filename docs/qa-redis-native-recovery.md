# Private Redis QA native-process recovery

This is a separate opt-in source variant, not production Redis activation. Enable native.qa.redis-persistence-enabled only with private native lifecycle, enabled QA callback gate and native.qa.callback-initially-paused=true. Require cache.redis enabled at127.0.0.1:26379, ttl30minutes and prefix qa:<32 lowercase hex run ID>:. Invalid combinations fail startup. Defaults and current Redis-disabled Q are unchanged. QA Lettuce commands have2second timeout; initial paused callback generation1, normal initial open generation0.

RedisGameRepository accepts the same native new-session admission reservations as InMemoryGameRepository only in this QA variant. Recovery caches existing sessions separately before native admission can open. Serialize and SET under the same session lock. Persistent player records carry exact aiControllerSpec and restore it into both session and PlayerIdentity across quick/shared/pod/tournament seating; old records decode with null selection. Repository-compatible lifecycle pending count includes quick lobbies and Redis lobby/sealed caches.

Startup requires an actual entire-prefix inventory <=64keys containing only game/game-lobby/lobby/tournament records; sealed/unknown inventories remain unsupported and fail. Primary recovery records share64-key/8MiB-per-value/16MiB-aggregate acceptance bounds. Missing observed keys, invalid snapshots, caught saves/loads and bound violations set sticky failure. Recovery cannot be marked complete after failure. Limits are checked after Redis client allocation and do not establish peak RSS. Actual guest memory/cgroups remain required.

Private recording health requires completed recovery/no persistence error, actual Redis PONG and GET bytes equal latest saved SHA. It remains separate from canonical completion. Updater-only private0600 native socket adds qa-redis-snapshot with protocol1, exact bootId/releaseId and actual gameId; require paused QA gate, active0, waiting0 and failures0. Actual GET bytes must match current locked session serialization and latest saved SHA. Response contains only bounded game ID/SHA/byte count/native state digest/manual flag/player identity digest, never raw snapshot or tokens. Native process recovery must preserve same exact source artifacts and nonterminal writer/journal prefix; existing row engineRevision is validated before appending resume.

No game removal or closeEvidence is allowed during interruption: it emits session_closed and seals the source. Stop only native cgroup, prove full closure/lock release, keep Redis alive, restart exact native initially paused, then verify actual stored snapshots and recorded resume/state_checkpoint/callback_resume_state against committed digest before callback resume. Source mock tests prove plumbing; actual guest transport/native restart/terminal qualification remains operator-owned and unproved until executed. Redis/guest restart, power loss and disk durability are outside scope.

No Redis service, binary, credentials or authority is supplied. The matched Gym qualification profile/root-role/closure and observer contract are documented in its docs/qa-redis-native-recovery.md. Operator alone stages reviewed exact dependencies, guest UID/DAC/service/cgroups and bounded controller. Guest2GiB/supervisor3GiB/zero-swap/900seconds and native512M–6G heap stay unchanged, with Redis64MiB carved inside guest bound. Current production and frozen Q receipts remain unchanged.
